# Database migrations

## Access

```bash
sudo docker exec -i sportconnect-db psql -U sportconnect -d sportconnect
# inspect: \dt   \d "ACTIVITEIT"   \di
```

## The live DB is the source of truth

`migrations/001_initial_schema.sql` is out of date. Known differences (2026-10-28):

- `"NOTIFICATIE".doel_url` exists live but not in 001.
- `"SPORTCONNECT_VRIENDSCHAP"` and `"SPORTCONNECT_PRIVATBERICHT"` are created at runtime by `ensure_friendship_table()` / `ensure_private_messages_table()` in `main.py`, with BIGINT ids (other tables use INT).
- Unused tables: `RAPPORTAGE`, `GEBRUIKER_BLOKKADE`, `BERICHT_BIJLAGE`, `GEBRUIKER_SPORTVOORKEUR`.

Always check with `\d` before writing a migration. Don't trust 001.

## Procedure

1. **Back up first:**
   `sudo docker exec sportconnect-db pg_dump -U sportconnect -d sportconnect -Fc > /opt/sportconnect/backups/db/$(date +%Y%m%d-%H%M%S).dump`
   (create `backups/db/` if missing).
2. Write `migrations/NNN_short_description.sql`, numbered after the highest existing file. Wrap it in `BEGIN; ... COMMIT;` and make it idempotent (`IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`).
3. Show the SQL to the user before applying anything destructive (DROP, type change, data rewrite).
4. Apply: `sudo docker exec -i sportconnect-db psql -U sportconnect -d sportconnect -v ON_ERROR_STOP=1 < migrations/NNN_....sql`
5. Verify with `\d`, then update the backend code that uses it.

## Conventions

- Quoted uppercase Dutch table names, Dutch snake_case columns, `<tabel>_id` primary keys (`INT GENERATED BY DEFAULT AS IDENTITY`).
- Add foreign keys and indexes for columns used in WHERE/JOIN (e.g. `gebruiker_id`, `activiteit_id`, `chat_id`).
- Existing timestamps are `timestamp` (no time zone). Ask before switching to `timestamptz`.
- No DDL in request handlers. New tables go in a migration, not an `ensure_*` function.
